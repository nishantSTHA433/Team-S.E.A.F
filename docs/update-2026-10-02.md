## Added capabilities

- Reference-led black, coral, lavender and amber layout, custom title bars, star emblem and functional bottom task strip.
- File manager with directory filtering, refresh, home/documents/downloads/exchange shortcuts, custom folder/file graphics, file sizes and readable modification timestamps. Open and confirmed recoverable Trash operations remain available.
- C: identifies Linux root. Additional GIO-mounted volumes receive stable D:–Z: labels. UUID is used when provided, otherwise the mount URI. Mapping survives restarts in `~/.config/lcars-desktop/drive-labels.json`; volume buttons refresh on mount events. These are visual aliases, not changes to Linux mount paths.
- Live NetworkManager D-Bus subscriptions, persistent status and degradation banner, Fedora desktop notifications for loss/restoration, and sound enabled by default for new preferences. Existing saved sound preferences are honored. The app must remain open (it may be minimized) to monitor events; this is not a login service.
- NetworkManager distinguishes verified online, offline, local/unverified, captive portal, limited and unknown. Internet status follows NetworkManager's connectivity policy, so detecting an upstream outage depends on that policy. Local link changes produce immediate events.
- Local diagnostics for adapters, addresses, routes and DNS; native network settings shortcut.
- Cancellable speed test: Cloudflare HTTPS endpoint, 10 MB download and 2 MB generated upload, 5-second connection timeout and 25-second timeout per stage. No user files uploaded. Provider sees the public IP. HTTP response time includes connection/TLS overhead; reported throughput is a bounded single-connection sample, not a certified maximum speed. See https://github.com/cloudflare/speedtest for the endpoint definitions.
- Calculator and read-only kernel/storage/process diagnostics. Application launching remains through GIO; third-party application windows are not globally re-skinned.

## Cursor/rendering mitigation

The observed corruption affected the Fedora desktop and RustRover as well as LCARS. A fresh VM boot restored the desktop. LCARS now defaults to GTK's Cairo software renderer before initialization, explicitly restores a normal cursor on pointer entry, and uses a software-rendering launcher on this X11 VM. It does not install a custom cursor theme or change system security settings. This mitigates LCARS GPU rendering triggers; it is not proof that every UTM/Xorg cursor or GPU defect is fixed. GTK renderer settings: https://docs.gtk.org/gtk4/running.html.
